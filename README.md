# 校园食堂饮食规划系统

## 项目简介

本项目为《算法与程序实践》课程设计作品，面向高校学生在食堂就餐时常见的“不会搭配、营养不均衡、预算难控制、口味或就餐方式受限”等问题，设计并实现一个基于食堂菜品数据的饮食规划系统。

系统使用 Python 与 Streamlit 构建交互式 Web 界面。用户可以录入性别、年龄、身高、体重、活动量等身体指标，系统会估算 BMI 与每日营养目标；用户也可以填写已进食记录、预算、口味偏好和就餐模式，系统再根据食堂菜品数据生成一日三餐和饮品推荐，并展示费用、营养摄入与推荐理由。

本项目不使用机器学习或深度学习模型，核心推荐过程采用可解释的贪心策略实现，便于展示算法执行过程和每一步选择依据。

## 算法说明

本项目选用区间调度类思想下的贪心算法作为核心算法。系统将饮食规划问题抽象为多约束下的菜品组合选择问题，在预算、营养目标、餐次、品类、口味偏好、就餐模式等限制条件下，为每一餐生成候选组合，并优先选择综合评分较高的方案。

算法基本流程如下：

1. 读取并校验食堂菜品数据。
2. 根据用户身体指标计算 BMI 和每日营养目标。
3. 结合已进食记录，计算当前营养摄入与剩余营养需求。
4. 按餐次、品类、预算、就餐模式和口味偏好筛选可选菜品。
5. 生成候选餐品组合，并计算组合得分。
6. 每次选择当前评分较优的组合，形成早餐、午餐、晚餐和饮品推荐。
7. 输出推荐结果、费用统计、营养对比和推荐理由。

组合评分主要考虑以下因素：

```text
组合得分 =
营养缺口匹配得分
+ 蛋白质补充得分
+ 膳食纤维补充得分
+ 品类搭配得分
- 预算超限惩罚
- 高脂高糖惩罚
- 已进食重复惩罚
```

该方法虽然不保证获得严格数学意义上的全局最优解，但具有运行速度快、逻辑清晰、结果可解释、适合交互式演示等优点。

## 课程算法对应关系

本项目对应课程要求中的“区间调度类算法——贪心算法”。

经典区间调度问题需要在资源有限、区间可能冲突的情况下选择合适方案。本项目将这一思想迁移到饮食规划场景中：每个餐品组合都可以看作一个候选方案，不同方案之间会在预算、营养目标、餐次结构、口味偏好和就餐模式上产生冲突。系统通过评分函数衡量每个候选组合的收益，并在每一步优先选择当前条件下更合适的组合，逐步构造全天饮食方案。

## 主要功能

### 1. 身体指标录入

用户输入性别、年龄、身高、体重和活动量后，系统自动计算 BMI，并估算每日热量、蛋白质、脂肪和碳水目标。

### 2. 已进食记录

用户可以按早餐、午餐、晚餐记录已经吃过的菜品。系统会将已摄入营养计入总量，并在后续规划中尽量避开重复菜品。

### 3. 规划参数配置

系统支持设置就餐模式、预算、口味偏好和推荐品类。堂食与外卖模式会使用不同费用规则。

### 4. 三餐智能规划

系统根据当前营养缺口、预算和菜品数据，使用贪心算法为早餐、午餐和晚餐生成推荐组合。

### 5. 饮品独立推荐

饮品不与正餐混合计算，系统会根据预算、糖分、热量和用户需求单独推荐。堂食模式下的免费例汤不会作为独立饮品推荐。

### 6. 费用核算

系统会统计每餐费用和全天总费用。外卖模式会额外考虑打包费、配送费等费用规则，并尽量控制在预算范围内。

### 7. 营养可视化

系统通过图表展示已摄入、规划后摄入与目标值之间的差距，便于用户理解推荐结果。

### 8. 推荐理由展示

每套餐品组合都会给出推荐理由，例如蛋白质补充较好、膳食纤维较高、预算较低、未包含油炸菜品等。

## 数据文件说明

系统主要使用以下数据文件：

```text
data/canteen_menu_final.csv
data/canteen_data_audit_final.csv
```

`canteen_menu_final.csv` 为食堂菜品数据表，包含菜名、价格、品类、商户、热量、蛋白质、脂肪、碳水等字段。

`canteen_data_audit_final.csv` 为数据整理与修正记录，用于说明菜品数据的清洗过程。

由于食堂菜品实际份量可能存在差异，项目中的营养数据为基于常见高校食堂份量的理论估算值，主要用于算法演示和相对比较，不作为专业医学或营养建议。
